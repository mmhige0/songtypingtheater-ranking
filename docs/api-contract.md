# API連携仕様案 v0.1

本書は提案。URL、フィールド名、型、ID方式、認証方式はゲーム開発者との合意前。
Unity/C#からホストがHTTPSでJSONを送信する。実コードはAPI合意後に実装する。

## 記録登録案

`POST /api/v1/plays`、`Content-Type: application/json`。

```json
{
  "playId": "a978c461-3a06-487d-80c8-552eb969031a",
  "songId": "001",
  "score": 123456,
  "isFullCombo": true,
  "hostPlayerId": "428d19c3-786c-4650-81c1-06848583d7fa",
  "players": [
    {
      "playerId": "428d19c3-786c-4650-81c1-06848583d7fa",
      "name": "プレイヤーA",
      "color": "#FF8800"
    },
    {
      "playerId": "f3e1a5de-d740-43d2-bce1-cd513c9b6790",
      "name": "プレイヤーB",
      "color": "#33AAFF"
    }
  ],
  "finishedAt": "2026-10-10T13:00:00Z",
  "gameVersion": "1.2.3",
  "isTaipen": false
}
```

上記は架空データ。色の実際の表現は未確認。色文字列と名前を分ける案であり、名前に装飾HTMLを入れない。

| フィールド | 提案型・必須性 | 意味 |
|---|---|---|
| playId | string、必須 | ホストが1プレイごとに発行するUUID案 |
| songId | string、必須 | ゲーム側の曲ID。先頭ゼロを保持する案。実型は確認する |
| score | number、必須 | チームのランキング対象得点。非負整数案。範囲・小数有無は要確認 |
| isFullCombo | boolean、必須 | 新規プレイのフルコンボ判定 |
| hostPlayerId | string、必須 | players内に存在するホストID |
| players | array、必須 | 重複IDのない1〜4人。ID・名前を必須、色を任意とする案 |
| finishedAt | string、必須案 | UTCまたはオフセット付きのプレイ終了日時 |
| gameVersion | string、任意 | 省略・nullを許容。未指定は不明 |
| isTaipen | boolean、必須案 | trueは登録対象外として拒否。省略でモードを推測しない |

人数はplayersの件数から算出。曲名・難易度・アーティスト名は曲マスターから取得する。
受信日時receivedAtはAPI側がUTCで記録し、クライアントからは受け取らない。

## ID・再送

- プレイヤーIDは初回発行してセーブデータに保存。ランダム8桁案よりUUIDを提案するが未確定。
- プレイIDは終了時刻から作らず、独立したUUIDを提案する。終了時刻は日時として別に送る。
- ホストは送信前にプレイIDとペイロードを保存し、通信失敗後も同じ内容で再送する。
- サーバーはplayIdに一意制約を設け、参加者と記録を1トランザクションで保存する。
- 同一ID・同一内容は成功として返す。同一ID・異なる内容は409にし、既存記録を上書きしない。
- 内容比較はJSON文字列の空白やプロパティ順に依存させない。参加者の送信順は表示順として保持する案。
- タイムアウト・通信失敗・429・5xxは待ち時間を増やして再送する案。上限・保存期間は要調整。その他4xxは内容修正なしで自動再送しない。
- ホスト切断時の代替送信は初期範囲外の案。対応するなら同じプレイIDの共有が必要。

## 応答案

| HTTP | 内容 |
|---|---|
| 201 | 新規登録成功。`{"playId":"...","status":"created"}` |
| 200 | 登録済みの同一内容。`{"playId":"...","status":"already_registered"}` |
| 400 | 型不正、必須項目欠落、重複参加者など |
| 401 / 403 | 採用する認証方式で許可されない送信 |
| 409 | 同じplayIdに異なる内容 |
| 422 | 未登録曲、TAIPENなど登録対象外 |
| 429 | 送信頻度超過 |
| 5xx | サーバー障害。再送可能 |

エラーは`{"error":{"code":"UNKNOWN_SONG","message":"曲が未登録です"}}`等の機械判定用codeを返す案。
新曲の情報登録を記録送信より先に行う。未知の曲IDから曲を無条件に自動作成しない。

## 日時・信頼性

先に達成した記録の判定にはfinishedAtを使う案。ただし端末時計は信頼できる時刻とは限らない。
receivedAtも残し、不自然な日時の許容幅・移行時の日時欠落処理は別途決定する。
プレイヤーIDは識別子であり、本人認証ではない。クライアントに埋め込んだ共通秘密だけで正当な得点を証明することはできない。
公開書込みAPIの認証、レート制限、入力サイズ・得点範囲チェック、誤記録除外の運用を公開前に決める。

## 閲覧APIの候補

- `GET /api/v1/songs`: 曲名・アーティスト・難易度による一覧検索、ページ分割。
- `GET /api/v1/songs/{songId}/rankings`: 人数、フル判定、プレイヤー検索、ページ分割。
- 全履歴を公開するAPIは初期必須ではない。

パラメータ名、ページング方式、同点順位、プレイヤー検索時の順位表示は画面設計と合わせて決定する。
