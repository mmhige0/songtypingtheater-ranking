# 要件定義

更新日: 2026-10-11（日本時間）

## 目的・規模

GoogleスプレッドシートのランキングをWebサイト化する。表示の重さ、検索の難しさ、新曲追加時のシート複製・数式修正・リンク追加（10分以上）を解消する。
フルコンボを記録し、同じメンバーの複数記録でランキングが埋まらないようにする。

想定: 約500曲、約1万記録、月約1,000記録増、閲覧者は1日数十人程度。
費用目標: 無料優先、有料でも月100円以内。実際の可否はサービス選定時に確認する。

## 確定した要件

| 項目 | 動作 |
|---|---|
| 公開閲覧 | ログイン不要で誰でも閲覧 |
| 分類 | 曲ID×人数（1〜4人）ごとにランキング |
| 掲載単位 | メンバーの組み合わせごとに最高スコアを1件表示 |
| 組み合わせ | プレイヤーIDを基準とし、A+BとB+Aは同一。集計用のteamKeyをPlayの列に保存 |
| 代表記録の選択 | 同じ組み合わせではスコアが高い記録を優先。同点ならフルコンボを優先、それも同じなら早い受付日時、最後にplayId辞書順 |
| フルコンボ | 通常ランキングの該当記録に印を付ける。別ランキングは作らない |
| 過去記録 | フルコンボ情報がなければ「不明」。未達成と区別 |
| 曲の別譜面 | 難易度違いはすでに曲ID・曲名が別。それぞれ独立したランキング |
| 譜面修正 | 同じ曲IDの誤字修正・文字数変更等があっても旧記録を同じランキングに残す |
| ゲームバージョン | 記録ごとに保存。v1新規送信は必須。移行分の不明は許容 |
| 検索 | 曲名・プレイヤー名で検索。代表記録を選択後、その記録のnameAtPlayで絞る |
| 絞り込み | 人数・フルコンボの条件で絞り込み |
| 新曲 | 管理者（運営者とゲーム開発者）が認証付きの曲登録APIで曲マスターへ登録し、登録完了後にゲームへ公開する（運用ルール）。登録後、ランキングが自動で用意される。曲ごとの画面や数式の手作業追加は不要 |
| 曲マスター | ランキングDBを正本とする。v1の登録手段は曲登録API（登録スクリプトまたはHTTPクライアントから呼ぶ）のみ。新曲はゲーム開発者が登録する。管理画面は後回し |
| 移行 | 現在のシートのみを元に、曲・人数・名前の組み合わせごとの最高スコアだけを移行。名前の順序は無視し完全一致で集約。新playerIdへは自動紐付けしない |
| TAIPEN | v1ではTAIPEN ONの記録はゲーム側で送信しない（ランキング対象外）。送信する記録は常に`isTaipen: false`。サーバーはONかつ4人の記録を受理できる状態を残し、ONかつ1〜3人は拒否する |
| 登録前提 | 成績送信はホストを含む全員の初回登録完了が条件。未登録参加者を含む新規成績は拒否 |
| 再送キュー | ゲーム側への推奨値：最大100件・初回保存から7日。超過時は古いものから破棄し、失敗履歴は残さない（ゲーム開発者とは未合意） |
| 認証 | ゲーム側が個別installationTokenを生成し、playerIdとともに通信前に永続保存して登録。ホストがBearer認証で送信 |
| 対象外 | 歌詞の保存・表示、本格的なスコア改ざん対策、譜面投稿フロー（v1後の将来構想） |

フルコンボ印は表示中の記録自身の判定であり、他のプレイで達成したことを示す印ではない。
異なる組み合わせ同士の同点は競技順位（1位、1位、3位）。FC優先は同じチームの代表選択だけに使う。
通常とサバイバルは同じランキング。TAIPENの4人記録を将来受け付ける場合は通常の4人ランキングに含める（v1ではゲームから送られない）。
新規プレイの日時はreceivedAt（API受付日時）だけを保存する。達成日時ではないことを表示文言でも区別する。
移行分の旧達成日時は保存せず、receivedAtにはインポート受付時刻を設定する。

## ゲーム連携で確認済みの事項

- Unity製。C#スクリプトからAPI通信できる。
- ホストが全参加者分を代表して送信する。
- 各参加者のID、名前、色、曲ID、スコア、フル判定を送信可能。
- プレイヤーIDは今後追加し、セーブデータに保存可能。
- ゲームバージョンは送信可能。v1新規送信で必須とする。
- ゲーム側でRandomNumberGeneratorの32バイトをBase64URL（パディングなし43文字）へ変換し、playerIdとともにAPI通信前に永続保存する認証方式に合意済み。
- 送信フォーマット・送信先は調整可能。
- 難易度やTAIPEN有無も送信可能。

## 保存・閲覧・運用方針

- 新規APIの全受理プレイ記録を保存し、通常ランキングには代表記録だけを表示する。誤記録除外時に次点を復帰できる。旧シートは最高スコアだけを移行する例外で、移行しない次点は復帰できない。
- 旧記録の日時・FC等は他の元データから補完できない。不明を推測せず、新IDへの紐付けは確認できた対応だけとする。詳細と実データを残さない運用は[移行設計](data-design.md#移行確定)を参照。
- 閲覧の設計案: ランキングと曲一覧はページ分割して取得する。全履歴をブラウザに送らない。
- 追加候補: アーティスト名検索、難易度の表示・絞り込みを追加する。
- 絞り込みの設計案: フルコンボ絞り込み時は、フルコンボ記録に絞ってから組み合わせごとの最高記録を選ぶ。通常最高が未達成でも、過去のフルコンボ記録が見つかる。
- 同じプレイの通信再送はDBのplayId一意制約とトランザクションで二重登録しない。同時再送も対象。
- 失敗成績は保存せず、失敗履歴機能は作らない。未送信キューは一時保存として別扱い。
- 初回登録の応答消失は保存済みの同じID・tokenの再送で対応する（新規201、同一200、異なるtoken409、失効済み401）。429はRetry-Afterに従って再送。詳細は[初回登録・再送仕様](auth-options.md)。IDだけで認証情報を再発行しない。
- Master Client交代・開始時参加者の管理はゲーム側の責務。Web側にPhoton固有の処理を追加しない。
- 管理の設計案: 記録は物理削除より管理者による除外を優先する。管理画面・権限の範囲は別途決定。
- 曲マスターの正本はランキングDB。現在の曲一覧シートはランキング移行完了後に廃止するため、移行時に曲番（=ゲーム曲ID）から一度だけ初期登録する。以降の曲情報はランキングDBで管理し、LyricDataCreatorはランキングの曲一覧APIから曲情報を取得する（逆方向の同期は行わない）。
- 登録前の曲への成績は422 UNKNOWN_SONGで再送されず失われる。ゲームへの新曲公開は曲マスター登録の完了後に行う運用とする。

## 将来構想（v1対象外）

譜面投稿フローの最終形は次のとおり。v1では実装しないが、データ設計はこの形に拡張できるようにする。

1. 譜面制作者がLyricDataCreatorで譜面を作成し「投稿」する。
2. LyricDataCreatorのサーバーがランキングアプリへ未承認曲として仮登録し、続けてDiscordへ譜面ファイル・曲情報を投稿する。
3. ゲーム作者が譜面を確認・ゲームに実装し、ランキングアプリで承認する（ゲーム曲IDを割り当てて本登録）。
4. 本登録済みの曲だけがランキング登録可能になる。

投稿の冪等性、Discord・ランキングの片側失敗、匿名投稿の制限、既存曲修正の再投稿の扱いはv2設計時に決める。

## 受入条件

1. 同じ曲・人数でA+Bの100点、90点、B+Aの110点があると、通常表示は110点の1件になる。
2. A+BとA+Cは別々に表示される。改名しても同じIDなら同じ組み合わせになる。A+BとB+Aの保存済みteamKeyは一致し、A+Cとは異なる。
3. 同じ組み合わせ・同点ならフルコンボが選ばれ、フル判定も同じなら早い受付日時、さらに同じならplayId辞書順で選ばれる。
4. 同じ曲IDの異なるゲームバージョンの記録も比較対象になる。
5. v1新規送信でgameVersion欠落を拒否し、移行時のバージョン・フル不明を未達成等に変換しない。
6. 新曲を登録すると、記録0件でもランキング画面を表示できる。
7. 同じプレイの再送で保存件数が増えない。同時再送も対象。同じplayIdの再送は本文を比較せず200を返す。
8. （サーバー側）TAIPENの4人記録は登録でき、1〜3人は拒否する。v1ではゲームからTAIPEN ONの記録は送られない。
9. 必要なページだけ取得し、件数増加で全件転送が発生しない。
10. 名前検索は代表記録の時点名だけに一致し、検索によって次点のスコアが表示されない。FC絞り込み時もFC記録から代表を選んだ後に検索する。
11. 旧記録は名前の組み合わせが同じなら最高スコアだけを移行し、新IDとの自動統合は行わない。同点の選択は再現可能にする。公開前は移行分を全削除して取り込み直せ、公開後は取り込み直さない。
12. 未登録参加者を含む新規成績は422 UNKNOWN_PLAYER。成績受付に伴う参加者の自動登録は行わない。
13. 管理用キーのない曲登録は401。同じ曲情報の再登録で曲・記録は変わらず、曲情報を修正しても既存のランキングと記録はそのまま残る。

具体的な応答時間目標は、ホスティング選定と測定条件を決めてから設定する。
