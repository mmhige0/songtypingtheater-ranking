# 要件定義

更新日: 2026-10-10（日本時間）

## 目的・規模

GoogleスプレッドシートのランキングをWebサイト化する。表示の重さ、検索の難しさ、新曲追加時のシート複製・数式修正・リンク追加（10分以上）を解消する。
フルコンボを記録し、同じメンバーの複数記録でランキングが埋まらないようにする。

想定: 約500曲、約1万記録、月約1,000記録増、閲覧者は1日数十人程度。
費用目標: 無料優先、有料でも月100円以内。実際の可否はサービス選定時に確認する。

## 確定した要件

| 項目 | 動作 |
|---|---|
| 公開閲覧 | ログイン不要で誰でも閲覧 |
| 分類 | 曲ID×人数（1〜4人）ごとにランキング |
| 掲載単位 | メンバーの組み合わせごとに最高スコアを1件表示 |
| 組み合わせ | プレイヤーIDを基準とし、A+BとB+Aは同一 |
| 代表記録の選択 | 同じ組み合わせではスコアが高い記録を優先。同点ならフルコンボを優先、それも同じなら先に達成した記録 |
| フルコンボ | 通常ランキングの該当記録に印を付ける。別ランキングは作らない |
| 過去記録 | フルコンボ情報がなければ「不明」。未達成と区別 |
| 曲の別譜面 | 難易度違いはすでに曲ID・曲名が別。それぞれ独立したランキング |
| 譜面修正 | 同じ曲IDの誤字修正・文字数変更等があっても旧記録を同じランキングに残す |
| ゲームバージョン | 記録ごとに保存可能。送信は任意で、欠落時は不明 |
| 検索 | 曲名・プレイヤー名で検索 |
| 絞り込み | 人数・フルコンボの条件で絞り込み |
| 新曲 | 曲情報登録後、ランキングが自動で用意される。曲ごとの画面や数式の手作業追加は不要 |
| 移行 | 現在のスプレッドシートの記録を引き継ぐ |
| 対象外 | TAIPENモードの記録登録、歌詞の保存・表示 |

フルコンボ印は表示中の記録自身の判定であり、他のプレイで達成したことを示す印ではない。
異なる組み合わせ同士の同点順位は未確定。

## ゲーム連携で確認済みの事項

- Unity製。C#スクリプトからAPI通信できる。
- ホストが全参加者分を代表して送信する。
- 各参加者のID、名前、色、曲ID、スコア、フル判定を送信可能。
- プレイヤーIDは今後追加し、セーブデータに保存可能。
- ゲームバージョンは任意項目として送信可能。
- 送信フォーマット・送信先は調整可能。
- 難易度やTAIPEN有無も送信可能。

## 採用を提案する仕様

- 全プレイ記録を保存し、通常ランキングには代表記録だけを表示する。誤記録除外時に次点を復帰できる。
- ランキングと曲一覧はページ分割して取得する。全履歴をブラウザに送らない。
- アーティスト名検索、難易度の表示・絞り込みを追加する。
- フルコンボ絞り込み時は、フルコンボ記録に絞ってから組み合わせごとの最高記録を選ぶ。通常最高が未達成でも、過去のフルコンボ記録が見つかる。
- 同じプレイの通信再送は二重登録しない。
- 記録は物理削除より管理者による除外を優先する。管理画面・権限の範囲は別途決定。

## 受入条件

1. 同じ曲・人数でA+Bの100点、90点、B+Aの110点があると、通常表示は110点の1件になる。
2. A+BとA+Cは別々に表示される。改名しても同じIDなら同じ組み合わせになる。
3. 同じ組み合わせ・同点ならフルコンボが選ばれ、フル判定も同じなら早い達成日時が選ばれる。
4. 同じ曲IDの異なるゲームバージョンの記録も比較対象になる。
5. バージョンなしの記録も受け付け、過去のフル不明を未達成に変換しない。
6. 新曲を登録すると、記録0件でもランキング画面を表示できる。
7. 同じプレイの再送で保存件数が増えない（API案の採用時）。
8. TAIPEN記録は登録できない。
9. 必要なページだけ取得し、件数増加で全件転送が発生しない。

具体的な応答時間目標は、ホスティング選定と測定条件を決めてから設定する。
