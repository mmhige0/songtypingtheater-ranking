# 決定事項・未決定事項

更新日: 2026-10-11（日本時間）

## 確定

- 曲ID×人数でランキングを分け、メンバーの組み合わせごとの最高記録を表示。
- 同じ組み合わせの同点はFC優先を維持する。異なるチーム同点は競技順位（1、1、3）。
- FC印は代表プレイ自身の値。過去の不明を未達成にしない。
- 別譜面は別曲ID。同じ曲IDの修正前後・ゲームバージョン違いは分離しない。
- Unity/C#のホストからHTTPSでJSONを送信。全参加者のIDを送信。
- プレイヤーIDはセーブデータに保存。提示v1を基にplayerId/playIdはUUIDv4とする設計。
- 認証は提示v1の個別installationToken方式を採用。初回にサーバーが発行し、ホストがBearer認証で送る。共通登録キー方式は採用しない。
- TAIPEN ONかつ4人の記録は残す。ONかつ1〜3人は拒否。
- 通常とサバイバルを分けない。対戦・Debug等の送信抑止はゲーム側。
- PhotonのMaster Client交代・参加者スナップショット管理はゲーム側の責務。Web側でPhoton固有の処理は実装しない。
- 全受理プレイを保存。playId一意制約とトランザクションで同時再送も重複防止。
- 失敗成績・失敗履歴は保存しない。成功済みの履歴と未送信の一時キューは別。
- colorはR/B/Y/Gの大文字のみ。小文字を正規化して受け付けない。
- 本格的なスコア改ざん対策は初期範囲外。個別トークンは正規プレイの証明ではない。

## 設計案として反映（最終調整）

- v1はfinishedAtを送らずreceivedAtで先着判定。これは達成順から受付順への変更。
- gameVersionをv1新規送信では必須に変更。移行分の不明は許容。
- 再送キューは最大100件・初回保存から7日。期限切れ・非再送エラーは破棄、失敗履歴なし。
- レート制限はplaysがIP・installationそれぞれ10分100リクエスト、installationsはIP1時間20リクエスト。運用設定として実測後に調整。
- フル絞り込みでは全受理記録のFC記録から代表を選ぶ。
- FC不明と未達成は同点の代表選択で同じ優先度とする。
- 個別トークン初回登録の応答消失対策: registrationSecretを事前保存し、サーバー発行tokenを期間限定で再取得する案。auth-options.md参照。復旧方法は未確定。
